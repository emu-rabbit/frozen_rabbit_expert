## 成本與工程驗證

- 在相同 100 pairs 上，耐久搜尋最佳化前後 200 筆雙臂非計時結果一致，candidate solver 時間從 170.366 s 降到 89.084 s（約減少 47.7%）。
- 相對 v1.0 的同一診斷集：完成 86 → 91、滿品質 66 → 68，solver 時間 118.494 → 89.084 s。抽樣及比較器一起變動，其策略效果屬整體比較。
- 新 seed 的 300 candidate episodes 累計 solver 時間 278.853 s／9,024 次推薦，平均約 30.90 ms；最慢 849.376 ms。
- 同批 v0.30 累計 3.269 s／9,107 次推薦。v1.1 的共同候選與續作比較約使用 85.3 倍 solver 總時間；本輪最佳化降低的是新架構自身成本。這項計算代價須連同品質收益、完整矩陣長尾及後續目標裝置結果一起判斷。
- 8-case observer 重播有 288 次推薦，p50／p95／p99／max 為 3.272／272.216／559.449／808.468 ms；百分位僅適用這 8 cases。
- Rust 90 tests 覆蓋 mechanics、狀態隔離、root 失敗機率、route interruption、最後 action 預算、單一候選與配對抽樣差異；耐久二分另與逐點窮舉對照。
- TypeScript、overnight tool typecheck、64 份文件治理與選定 Rust 檔案格式檢查通過。8-case observer 的 stop／progress／quality／actions 與 readiness 對應結果一致。
- 主要求解器的 Web 3 秒 watchdog、獨立快速求解器及目標裝置驗證留在採用階段。
- Runner 19 tests 通過；實測 3 秒 invocation 中止後沒有殘留 Rust episode，原 smoke 成功續跑，status-only 及再次 resume 跳過已完成 shard。單／雙 worker 共用的 80 筆雙臂結果排除 timing 後完全一致。完整 overnight 只有 0/150-shard 預檢。
