# v1.5 完整收尾與查詢快取研究

2026-08-29。v1.5 回到 v1.3 的全球色、完整收尾與比較規則，沒有採用 v1.4 的起手／局部品質擴充。此版仍在成本確認，尚未交付 overnight。

## 快取契約

只快取本來就各自建立固定搜尋預算的三類純查詢：進展路線、進展可行性、品質爆發。共用預算的內層搜尋不快取，不跳過應消耗的搜尋預算。每次推薦最多保存 4,096 筆，包含找不到 witness 的結果；滿了仍照常計算。

Key 保存 mechanics、工匠、完整狀態與 query 參數；快取只在一次明確版本的推薦中有效，離開或巢狀返回後恢復原 owner。原版預設不啟用。後續變體只在尚未終局且進展未滿的「進展／恢復查詢」投影掉品質、內靜與品質專用增益；這些查詢沒有品質技能，且既有搜尋本就假設必要品質已滿。終局／超進展輸入不投影。

## 已完成檢查

- `v150-cache-focus` 600 cases、`v150-cache-broad` 1,200 cases，和封存 v1.3 的完全相同案例比較，全部技能序列、終局、亂數 cursor、最終完整 state 與 planner context 一致；只忽略 solver identity、案例標籤與計時。
- 同批對 v1.1 的總 native 成本比仍為 focus 1.403、broad 1.246，沒有達到原定 1.10 護欄。
- 四個慢案例的 158 個相同實際狀態探查中，純完整 key 僅命中 1,984/78,604 次查詢，v1.3／v1.5 累計約 3.00／2.98 秒。這是所選慢案例的診斷，不是整體速度保證；目前不足以把快取稱為有效效能突破。
- Release Rust tests 通過，涵蓋 scope、巢狀恢復、false／None、key 差異與飽和後繼續計算。進展投影另外逐九種球色、兩種必要品質契約對照未快取搜尋。

`v150-projected` 已完成相同 1,800 cases，全部非計時行為仍精確相同，見 `projected-*-parity.json`。對 v1.1 成本比為 focus 1.395、broad 1.224，仍不足以通過護欄；後續版本不強留這項快取。原始資料在 `evaluation-runs/v120-development/<label>`，快取統計可由 [cost probe](../v130-development/profile-cost.mjs) 重建。尚未動用新的 81000000 確認資料。
