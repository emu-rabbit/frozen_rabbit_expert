# 基本路線探針：開發紀錄

2026-08-29。500 組參考已完成第一輪；以下路線比較只使用 `optimal` 且重播一致的案例，不是採用或保留集證據。程式為 `native/craft-kernel/examples/normal_route_probe.rs`，**未接入任何 solver version**。

## 觀察與假說

F02/E06（index 15）參考品質 18,349，當前實驗在全通常球的 8 次技能成敗平均為 12,099；具體 trace 顯示內靜中途的高額耐久投資、增益期間的非加工動作，以及無連擊折扣的高 CP 加工。這不是由一次高速製作失敗即可解釋的差距。

探針把加工連擊、buff 與消耗者作搜尋單位，但每個技能仍用同一 Rust mechanics 逐步驗證；搜尋完整能交付的路線。搜尋中同時保留不同進展比例的候選，避免品質分數把所有有完工資源的分支篩掉。CP、耐久、內靜與剩餘進展只用於啟發式排序，不冒充理論上界或成功率。所有狀態共用規則，無配方／裝備 ID 或 seed 例外。

## 500 格基本路線矩陣

目前探針 binary SHA256 `c6f84e087742a6b0c629cca7372a0f8fd008817be4d958a1eea7930db89f106d`；500 格輸出 SHA256 `236a421250477feb735eb77c4879de1be4ab94c3404c31a80e7825f9212fd27b`。它保留品質密集、既有 expanded、compact 三個**通用**搜尋各 400,000 transitions，再增加 200,000 transitions 的混合資源 arm；四種都跑全部輸入，沒有按 ID 或 benchmark 結果挑模式。新增 arm 把掌握／崇敬和細緻合成、精密製作、模範製作等低資源結構一起作搜尋 edge，每招仍用正式 mechanics 重播。此組使用 width 256，合計上限 1,400,000 transitions。

探針在 500 格都找到推滿進展的路線。Hard-quality 未達必要品質時保留真實 `Failed`，只拿其品質作「還差多少」診斷，不計交付或 U；140 格 hard-quality 中有 6 格確實達成滿品質。下表只納入 412 個 `optimal` 且重播一致的 Raphael 格。

| 目標 | 可比較格 | 探針 Q 加總／Raphael Q 加總 | 至少達 Raphael Q 90% |
| --- | ---: | ---: | ---: |
| 一般收藏品 | 257 | 3,175,791／3,362,928（94.4%） | 185/257 |
| hard-quality | 115 | 1,362,864／1,488,875（91.5%） | 69/115 |
| HQ | 16 | 181,744／202,543（89.7%） | 6/16 |
| 連續收藏品質 | 24 | 305,930／328,982（93.0%） | 23/24 |

這不是成功率，也不是跨配方玩家價值。原始品質點數的加總比只回答基本資源路線是否接近參考；正式判斷仍需各格 U、交付、滿品質與球色世界。相對上一個三-arm 版本，新 arm 在 500 格為 54 勝／0 負／446 同，原始品質合計 +21,317；低於 Raphael 80% 的 `optimal` 格由 19 降至 10，低於 90% 由 141 降至 129。平均計算時間 107.6→126.0ms（+17.1%），p95 188.6ms；這仍是同機離線研究量測，不能作目標裝置 latency gate。

相對前一個兩-arm 探針，保留每個舊 arm 的完整 400,000 transition 預算後，新品品質組合在 500 格為 155 勝／0 負／345 同，原始品質合計 +52,882，平均時間 +57.4ms。先前縮分舊 arm 預算的版本曾出現 12 格退步；完整預算確認那是 beam 競爭，不是新技能段本身有害。

## 球色路線探針

`condition_route_probe.rs` 明確保存尚未走完的基本路線，依實際 state 比較照走、插入任一合法技能、取代接下來一至兩招，以及把十步內既有技能提前。第一招可以是機率技能；成功率與失敗結果按 mechanics 權重合併，失敗分支沒有完成就得到零交付效用。後續每個觀測結果重新驗證路線，必要時重排。未來球色先假設 Normal，因此它是球色反應假說，不是完整 IID 最佳化器。

## 未通過的正式策略整合

依據基本路線的連擊缺口，曾讓現有 `exp-condition-route-risk` 在開場與低內靜階段額外比較 Reflect／Muscle Memory、Preparatory Touch／Prudent Touch 及加工連擊。這是共用 state signal，不是 ID patch；但在既有 canonical 101000000 開發矩陣 600 pairs 明確退步：

- 全體完成 540→539、平均 U +0.02239、滿品質 +9，計算比 2.076；原實驗在同一矩陣為完成 540→544、U +0.04030、滿品質 +28、計算比 1.390。
- 主要 hard-quality 38→37；主要 HQ 完成 8→7、U −0.12875；主要 progress-only 144→143。
- 額外候選不只擠壓原本較好的球色／收尾選項，也讓一般收藏品滿品質 91→89。即使部分普通品質值上升，不能用它掩蓋交付與 HQ 退步。

因此 runtime 改動已撤回，沒有 solver identity 或版號。完整切片保存在 `condition-iq-route-canonical-focus-summary.md`，binary／input／逐格 paired results 保存在 evaluation run。這也證明不能把 Raphael 的技能頻率差直接抄成 root proposals；需要把「整條較好基本路線」作共同 forecast，才有正確的機會成本。

局部搜尋觀測約 10–55ms，當時另有兩個 Raphael workers，僅用來估計量級，不能當成獨立 latency 驗收。完整比較、不同目標、弱裝備、球色重播、實際中斷／恢復與推薦耗時尚未驗收；不足以升版或交付 overnight。

## 下一個結構問題

要把基本路線帶入正式逐步球色決策，需把尚未執行的路線放進版本化 `PlannerContext`，並在實際技能／球色後重新驗證。不能用 process-global 暖快取偷偷決定路線，否則 replay 會依執行順序改變。下一步應讓既有強策略與基本路線作同一套球色 forecast，而不是以目前較弱的路線探針取代它；重用剩餘路線，失效時才搜尋，才能守住時間。

確定路線只是一個有價值的候選。隨機技能與球色機會繼續依滿品質／品質期望及失敗成本比較，不被這個參考強制取代。

`portfolio_initial_probe.rs` 另檢查四個開發格的正式實驗初始候選。三格只有 Semantic 的 Reflect；F02/E06 另有一個 Delicate Synthesis 進展候選，所有候選的 `continuation_actions` 都是空的。也就是說，現有 `maximum_quality_finish_actions` 只會在已能用短品質爆發達滿品質時建立完整 suffix，開場沒有「先累積內靜、投資耐久、最後爆發並完工」的全程候選。這和 Raphael trace／基本路線探針指出的缺口一致。

後續實作界線因此更清楚：不是再加一個開場加工，而是建立通用的完整路線 capability；將剩餘 action queue 放進顯式、版本化 planner context；實際球色或玩家偏離後驗證、可中斷及恢復；既有隨機／球色候選與完整路線使用同一個 paired forecast。完成前不能升版或宣稱可跑 overnight。
